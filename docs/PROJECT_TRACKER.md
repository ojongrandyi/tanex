## System notes (codebase walkthrough, still accurate before phase A)

**Shape.** One Node process. `server/index.ts` (Express 5) serves `/api/*` and the built SPA from `dist/`. Dev: Vite on :3000 proxies `/api` to Express on :5000. Build: `tsc` (src) → `vite build` → `tsc -p tsconfig.server.json` → `dist-server/`.

**Routing (since D.1).** No router library. Paths from the route table `src/router/routes.ts` (`matchPath`, `pagePath`, `legacyHashToPath`; also used by the server). `src/router/navigation.ts`: `startRouter()` (main.tsx; rewrites legacy `/#/…` links, listens to `popstate`/`hashchange`), `navigate()` (History API), `subscribe()`, `useRoute()`, `hrefFor()`; `src/router/Link.tsx` (`<Link>`, `isPlainClick`). `src/App.tsx` keeps `currentPage` in state, synced from the path; `getInitialPage()` resolves the first paint. Server: `server/publicPages.ts` answers known paths with `index.html` (301 to the canonical spelling), everything else falls to the 404 handler. Since D.2 every HTML response is rendered by `server/render/pageMeta.ts` (per-page head between the `tx:head` markers, `<html lang>`), and `sitemap.xml` comes from the same route table. Admin: `isAdminPath()` (exact `/private-user/`) → `admin`; on localhost `#/admin` also opens it. Any other path → `not-found` (server answers 404). Console code is a lazy chunk; public pages are lazy chunks with their CSS kept in the main bundle (`src/pages/pageStyles.ts`).

**Frontend ↔ API.** `src/services/api.ts` holds relative `fetch('/api/...')` calls. `AdminDataProvider` wraps the whole app but loads console lists only with a session. Public tracking: quote IDs (`QR…`) first, then `GET /api/track/:id` (PII-masked). Public contact info from `GET /api/settings`. `simulationEngine` broadcasts across tabs through localStorage `ngf_live_shipment_stream`.

**Server progress.** `server/progress.ts` advances progress and map position on every read, importing `src/services/{routingEngine,planningEngine,geocodingService}.ts` (shared with Node, must stay DOM-free). Must skip LOCAL/INTERCITY shipments from G.1.

**Tracking IDs.** Allocated only by `server/trackingIds.ts` via `src/shared/trackingId.ts` (`crypto.randomInt`), prefix from `TRACKING_PREFIX`. Piece labels `<ID>-NN`; `/api/track` normalises input and resolves piece labels.

**Auth (from B.2–B.6).** Staff accounts sign in with email or phone (IAM_RBAC_SPEC §5–§6); sessions in the SQLite `sessions` table (cookie `tx.sid`), so restarts keep people signed in. `ADMIN_PASSWORD_HASH` is now only the first Super Admin's bootstrap hash. Every console route uses `requirePermission` (spec §7, all mounts in `server/apiRoutes.ts`); staff writes are audited with the `audited(...)` route middleware (`server/audit.ts`). `must_change_password` is enforced by the console (forced change screen, B.4) and by the API (403 `PASSWORD_CHANGE_REQUIRED` outside `/api/auth/*`, B.6). Email (B.6) goes through the `email_outbox` table and a 30 s worker (`server/mail/`); without `SMTP_HOST` it is off, and so is "Forgot password?". `scripts/routeGuards.test.ts` fails when a route under `server/routes/` is reachable signed out without being on its public list. The console reads the session through `src/auth/AuthContext.tsx`; what each user sees is decided by `can(key)` and `src/admin/views.ts`, while the server stays the authority.

**DB.** `node:sqlite` at `DB_PATH` or `<cwd>/data/<DB_FILE>`. WAL, foreign keys on. Schema in `initDatabase()` with try/catch `ALTER` migrations. Soft delete (`deleted_at_ts`); `/permanent` hard-deletes from trash. Uploads in `UPLOADS_DIR` (`images/`, `proofs/`).

**Fragile / worth knowing**
- `server/db.ts` opens the database when it is imported, which in `server/index.ts` happens before `dotenv.config()` runs. A `DB_PATH` set only in `.env` is therefore ignored by the server (it falls back to `data/tanex.db`); set it as a real environment variable (Hostinger panel) or fix the import order. `scripts/create-super-admin.ts` loads dotenv first and does honour `.env`, so the two can disagree if `DB_PATH` lives only in `.env`.
- `/api/diag/storage` returns server paths; remove after the persistence check (#59).
- ~~`GET /api/settings` is public and returns the whole settings object~~ Fixed in B.3: visitors get the public fields only (`PUBLIC_SETTINGS_FIELDS` in `server/routes/settings.ts`).
- `SESSION_COOKIE`, the logout `clearCookie` and the `ngf_live_shipment_stream` key must change together.
- `'New York'` / `'August 24, 2026'` fallback defaults remain in the server insert path (`server/routes/shipments.ts`).
- Schema columns `*_state`, `*_zip`, `*_lbs` are U.S.-shaped; they stay (rule 10).
- `CreateShipmentView.tsx` (≈4,100 lines), `DocumentCenterView.tsx` (≈2,000), `TrackResultPage.tsx` (≈1,400), `AdminDataContext.tsx` (≈1,100): edit surgically.
- Payment method catalogue: `src/shared/paymentMethods.ts` (US/EU-centric today; MoMo/OM added in E.6).
